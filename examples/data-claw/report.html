DataClawEval 将 Data Agent 评测从单步查询生成推进到真实执行环境中的数据探索、实现、调试、物化与验收，并用任务级确定性 grader 同时检查最终数据产物和工程过程。

Why it matters

对数据工程而言，最危险的问题往往不是 SQL 无法运行，而是任务显示成功却产生错误数据；论文把静默错误、跨引擎差异、重复运行稳定性和工具成本放进同一证据链，直接对应 Data Agent 产品的验收、观测和接管机制。

Bottom line

这是一篇对 Data Agent 评测设计很有价值的 benchmark 论文，但不能把其综合分解释为生产成功率，也不能把固定 CodeBuddy scaffold 下的模型后端排名外推为完整 Agent 产品排名；单企业来源、任务重建、单次主实验和缺少跨 Harness/人工基线仍限制结论。

Focus questions

  • 这篇工作是否真正覆盖端到端数据工程，而不只是 Text-to-SQL？
  • 证据能否支持对 Data Agent 可靠性、跨引擎能力和评测方式的结论？
  • 哪些机制可以迁移到 Data Agent 产品、数据质量平台和持续学习闭环？

Method and assumptions

Problem

现有 Text-to-SQL 与数据分析 benchmark 多以固定 schema 下的查询或最终答案为目标，缺少对真实数据工程任务中 schema 探索、跨引擎执行、调试、结果物化与过程可靠性的联合评测。

paper_claimconfidence: highevidence: moderatep. 2 · §1 Introduction and Table 1 · Table 1

Approach

方法把任务构造和 Agent 评测耦合：先把生产实现转成可公开执行且可辨识的任务，再让 Agent 在按 case 初始化的 Docker 环境中交付产物，由任务专属 grader 给出产物分与过程分。

paper_claimconfidence: highevidence: strongp. 4 · §3 DataClawEval · Figure 2

Workflow

对专业数据工程师编写的生产代码进行脱敏、去重和分层采样。

paper_claimconfidence: highevidence: moderatep. 4 · §3.1 Stage 1 · Figure 2

使用 LLM 根据实现和 schema 重建用户意图与输入表，并通过执行循环修订任务。

paper_claimconfidence: highevidence: moderatep. 4 · §3.1 Stage 2 · Figure 2

专家扰动正确实现，要求正确实现与扰动实现对合成输入产生可区分输出，以降低“错误实现也能通过”的假阳性。

paper_claimconfidence: highevidence: moderatep. 4 · §3.1 Stage 3 · Figure 2

任务级 grade.py 根据业务语义检查可执行性、schema、行级结果、数值和分类正确性，并由多名专家审计。

paper_claimconfidence: highevidence: moderatep. 5 · §3.1 Stage 4/5

每个 case 在独立容器中启动所需数据服务和工具；Agent 看不到参考实现与 grader，结束后再在同一环境执行评分。

Calibrated judgment

DataClawEval 对 Data Agent 的最大价值不是提供一个可营销的总分，而是给出“可执行任务 + 可辨识输入 + 确定性产物验收 + 过程轨迹 + 失败分类 + 重复运行”的评测骨架；若补上跨 Harness、人工基线、长期运维和持续学习回归，它更可能接近真实数据工程准入体系。

data-agent perspective

Data Agent 产品应把任务建模为需求、输入数据、转换逻辑、输出契约和验证证据，而不是只有自然语言与 SQL 文本。
